缘起

校园网认证大概是每个住宿舍的学生的共同记忆：打开浏览器，跳出一个门户页，输学号密码，点登录，网通了。然后第二天早上起来发现又断了，再登一次。宿舍里同时有手机、电脑、平板，于是每天要重复这个动作三到五遍。

更麻烦的是，学校的策略是”一个账号限制两台设备”。插了路由器之后，路由器算一台，手机算一台，电脑就没了。

所以很自然地想：能不能让路由器把这个认证包了？ 让整间宿舍在校园网看来”只是一台设备”，同时如果再叠几条线路，是不是还能把带宽也叠起来。

网上的方案不少，但大多是给一个脚本就完事，配置全靠改 Shell 变量，掉线了还得自己去看。我想要的是一个能长期放着不管的东西：有服务保活、有界面能改配置、出问题能看日志。

于是就有了这个项目。

先搞清楚”认证”到底是怎么回事

门户不是你想的那样

第一天我理所当然地认为：认证网关是 10.0.1.51，那我 curl http://10.0.1.51/ 不就能拿到登录页了吗？

拿是拿到了，但没有 queryString：

真正的登录页长这样，它的参数是门户主动派给你的：

而这个跳转脚本，只在你的设备”还没认证”时，被塞在别的 HTTP 响应里——比如你访问 http://connect.rom.miui.com/generate_204，门户会把响应整个换掉。

换句话说：queryString 只能在”被劫持的请求”里抓到。等你已经在线了，门户就放行，你再也抓不到它了。

更微妙的是，里面那几个哈希值（wlanuserip、mac、nasip）是 NAS 按你的源 IP 和 MAC 现算的，跟”是谁发起的这次请求”强绑定。所以它不能缓存、不能复用，必须在目标网卡上现抓现用。

这一条后来成了整个插件里最容易写错的地方：如果抓 queryString 的时候用的是默认路由网卡，那认证的就不是你想要的那条线。

架构上的一个取舍

第一版我犯了个很典型的错误：把”账号”和”线路”当成了同一个东西。

配置大概长这样：

create_vlan=1 就表示”给这个账号单独建一条 macvlan 通道”。看起来挺省事——加一个账号就等于加一条线路。

问题很快暴露了：同一账号多拨才是这个场景的主力用法。学校只给一个能用的账号，想叠带宽就得让同一个账号同时开好几条线路。这时候”账号”和”线路”必须是一对多，但我的模型是一对一。

改成一对一之后，配置变成了这样：

这其实是把名词还给数据：一个账号是一份身份（学号密码），一条线路是一次会话（一张网卡、一个 IP、一个 cookie）。它们生命周期不同、数量关系不同，硬塞进一个结构里，迟早要在别处还债。

同理还有一条硬约束：每个账号最多两条线路。因为学校多半限制同账号并发会话数，你配五条也是白搭，不如在界面上直接拦住——让用户在犯错之前就知道边界在哪。

踩坑实录

这一节是本文最值的部分。功能代码大概写了一天，剩下的时间基本都在跟”不报错但也不工作“搏斗。

坑一：mwan3 的策略名有 15 字符上限

多线路均衡交给 mwan3。一切看起来都对：interface 建了、member 建了、policy 建了、rule 也放到 default_rule 前面了。

campnet_balanced 是 17 个字符，超了。mwan3 的做法是警告一句然后把整个策略丢掉——不建、不报错、不生效。

改成 campnet_bal 就好了。

mwan3 的策略只保留 metric 最小的那批成员。所以”想让 N 条线均衡”的前提是它们 metric 必须相同；metric 不同就退化成故障切换了。这一点文档里写得很含糊，我是在代码里读出来的。

坑三：jshn 会给非标量返回一个”类型标记”

这个坑最阴，因为它让整个前端界面从建立起就没工作过。

LuCI 的 rpc.declare 有两种写法：

params 是数组时，LuCI 按位置传参：得写 getLog(200)。

而我写的是 getLog({ lines: 200 })——按对象传参。于是服务端收到的参数是嵌套对象 {"lines":{"lines":200}}。

到这里还只是”参数传错了”。真正要命的是接下来：

jshn 对 object / array 不返回内容，而是返回它自己的类型标记（J_T1 = Table 1，J_A1 = Array 1）。

于是：

  • tail -n "J_T1" 日志文件 → 输出 0 行 → 日志页永远显示”暂无日志”
  • campnet auth J_T1 → 找不到账号 → “登录”按钮点了没反应
  • setSecret 把用户名和密码写成一串 J_T1

全都是”静默失败”：界面不报错，只是什么都不发生。从用户视角看，就是”这插件根本不能用”。

坑四：macvlan 把整机的默认路由抢走了

这个是纯粹自找的，而且后果最严重——我把路由器搞断网了。

测试新网卡时我顺手跑了 udhcpc -i camptest，用的是默认脚本。默认脚本里有一句：

主 wan 的默认路由 metric 是 0，新网卡也是 0。结果整机默认路由被顶掉，SSH 直接失联，只能靠人现场断电重启。

修法很直接：新建的接口必须显式抬高 metric。

后来我把这条也写进了插件的注释里，因为任何”新建一个 WAN 口”的插件都会遇到同一个问题。

坑五：说明性文字会把界面毁掉

这一条不算 bug，算审美。第一版的界面长这样：每个配置项下面挂一段两三行的中文说明，一屏放不下五个字段，滚动条拉到底还有一大段”多播均衡原理”。

我后来重新想了下这个界面到底该回答什么问题：

  • 状态页该回答：”我现在通不通网？走几条线？这条线是谁的？”
  • 设置页该回答：”我怎么把它改成我要的样子？”

说明文字回答的是第三个问题（”它为什么这么设计”）——那个问题应该交给 README。

于是做了一轮删减：

  • 每节描述最多一行
  • 12 个晦涩的认证参数（pageid、templatetype、vlan……）默认折叠，勾”展开高级参数”才显示
  • 状态页首屏放一条横幅直接说结论，而不是让用户自己从表格里读
  • 破坏性操作（撤销线路）挪到页尾独立的”危险操作”区，并加二次确认弹窗

顺手挖出来的两个细节

状态徽标的颜色根本不生效。

我一开始用了 label label-success / label label-warning 这套 class。后来发现本机主题是 Argon，而它的 CSS 里根本没有 .label-success 这类修饰类——只有裸的 .label，背景固定灰色。

也就是说，”用颜色表示状态”这件事在深色主题下压根没生效，所有徽标都是一样的灰。改成自绘（显式给底色 + 白字）才是可靠的。

只读页面会多出一个没用的按钮。

LuCI 的 luci.js 里，页脚的”保存并应用”按钮是按视图钩子是否存在渲染的：

只读页只写 handleSave: null 是不够的，还得补 handleSaveApply: null、handleReset: null——否则会继承原型上的方法，然后页脚冒出一个点了没反应的”保存并应用”。

现在的样子

三页：

  • 状态总览：顶部横幅一句话说结论；下面是线路表（线路 / 归属账号 / 设备 / 状态 / IP / 最近结果）；
    再下面是门户回传的实名信息——学校门户的 getOnlineUserInfo 接口其实会返回姓名、学号、用户组、余额，
    这个之前完全没用上，现在直接展示出来了。
  • 插件设置：账号和线路都是表格（表头即字段，细节收进 Edit 弹窗）；帐密改成每个账号一行直接填，
    不再是”先在下拉框里选账号”；版本区可以一键检查 GitHub 上的最新 tag。
  • 插件日志：行号选择、级别过滤（INFO/WARN/ERROR）、自动刷新。

一些不算结论的结论

写这个插件最大的收获，不是学会了锐捷的门户协议，而是反复被同一件事教育：

“没报错”和”在工作”之间，隔着一整个太平洋。

mwan3 的策略名超长，它警告一句就丢掉；awk 的 exit 什么都不输出，看起来像”没改动”；jshn 给对象返回 J_T1，看起来像个正经字符串。这些都不会让程序崩溃，只会让它安静地什么都不做。

所以后来我给自己定了个规矩：凡是”静默失败”的地方，都要显式地把它变成”可见的失败”——

  • 参数类型不对就回一句人话，而不是让它变成一串 J_T1
  • 配置写不进去就报错，而不是 return 0
  • 界面取不到数据就说”取不到”，而不是显示成”暂无数据”

至于界面，最大的体会是：好的界面不是把话说全，而是把话说在正确的地方。配置项旁边应该只有一行字，而且那一行应该告诉你”填错了会怎样”，而不是”这个字段的历史渊源”。

——毕竟，路由器这种东西，装好了就该忘了它。
